# Repository guidance

- Maintain the fork on `downstream/patch-build`; application changes belong in the ordered downstream patch queue and are built from a prepared tree. See [downstream/README.md](downstream/README.md).
- `Release` is the sole full-platform test, build, packaging and publication gate. Before release mutations, the wrapper prepares one tree and runs local preflight: on Linux and macOS, a Windows Release solution build and the `net10.0` Core and Presentation tests; additionally, Linux runs a headless CMake build and CTest, while macOS runs `swift test`. Linux excludes four Windows Core tests requiring unsupported `FileIdentity`; macOS does not filter them, and native Windows `Release` runs all four. See the downstream README for their names. This requires the .NET 10 SDK plus the host's CMake/C++ dependencies or Swift toolchain. Host-specific checks do not validate the other OS, native UI or release packaging; these remain with `Release`. `--plan` skips preflight and its toolchain requirements. Do not launch standalone CI/Linux workflows or duplicate the full Release pipeline locally. Small targeted checks for a concrete bug or this maintenance tooling are allowed. Commit and push the fixes to `downstream/patch-build`, then use the release script; a failed Release job blocks publication.
- Use `bash downstream/release.sh --plan` for read-only release inspection and `bash downstream/release.sh` to tag the latest already-committed `downstream/patch-build` and wait for publication. The script does not stamp versions, create commits, or modify the patch queue or documentation. Release builds derive their version from the tag via `GITHUB_REF_NAME`. The wrapper queries the latest upstream release automatically and blocks if its tag commit differs from the configured pin; migrate and commit the pin and patch queue before retrying.
- An unpublished candidate may be retried; published releases, tags and assets are immutable. Changes after publication require a new fork version and tag.
- Do not initiate a real release without explicit authorization. See the downstream release guidance for prerequisites and details.
